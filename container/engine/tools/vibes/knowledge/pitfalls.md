# Pitfalls
> Bugs that compiled green and shipped: the publicizer trap, Character.Message arity, IMGUI buttons, cloned buttons' listeners, the 1E-18f tooltip sentinel, the world-level item stamp, UnifiedPopup's panel tree, joining a server.

1. **The publicizer trap.** You compile against `assembly_valheim_publicized.dll` where every member is public; the game runs the REAL assembly. Calling a private method or reading a private field compiles green and throws `MethodAccessException`/`FieldAccessException` at the call site the first time that line runs -- one landmine per reference, each on its own timer. ThorsKist shipped eight. Rules: inside a Harmony patch use `___fieldName` injection or `AccessTools.Field/Method` + reflection (`Traverse`), never a direct `obj.m_private`; or use `[HarmonyPatch]`'s own access. If you must reference a private member directly, say so and list it, and prefer the `BepInEx.AssemblyPublicizer.MSBuild` runtime-safe pattern (IgnoresAccessChecksTo) only when the pak confirms it. A green build is not an oracle for this.
2. **`Character.Message` arity.** A later game patch added a 5-argument overload (`MessageType, string, int, Sprite, bool`); a patch declared on the method NAME alone throws `AmbiguousMatchException` at `PatchAll`, the plugin loads, and NO patch applies. Always pass the parameter type array for any method that might be overloaded.
3. **`___field` type mismatch** (NoMovementPenalty 1.0.4): `ref float ___m_equipmentModifierValues` for a `float[]` field compiled and emitted bad IL; newer HarmonyX validates and the patch silently never applies. Match the field type exactly; confirm with `game_source`.
4. **IMGUI buttons draw but never click.** `GUI.Button` in `OnGUI` renders in Valheim's menu and never returns true (the game uses the new Input System). Build UI by cloning a game button: `Object.Instantiate(FejdStartup.instance.m_menuButtons[0].gameObject, canvas.transform, false)` -- parent to the CANVAS, not the layout column.
5. **A cloned button keeps its handler.** `onClick.RemoveAllListeners()` removes only runtime listeners; Inspector-wired persistent ones stay. Disable them: `for (i < onClick.GetPersistentEventCount()) onClick.SetPersistentListenerState(i, UnityEventCallState.Off)`, then `AddListener`.
6. **`1E-18f` is load-bearing.** `Player.AppendEquipmentModifierTooltips` skips a modifier that is exactly `0f`, so the tooltip row disappears. To neutralise a penalty but keep its row, use `1E-18f` (formats as `+0%`). Do not "tidy" it to zero.
7. **World-level item stamp.** `Inventory.AddItem` sets `item.m_worldLevel = Game.m_worldLevel` and `GetItem`, `CountItems`, `HaveItem`, `RemoveItem` (default `matchWorldLevel=true`) ignore items stamped below the current world level; `GetItem` has NO opt-out. For any virtual/shared inventory iterate `GetAllItems()` yourself.
8. **UnifiedPopup's tree.** `UnifiedPopup.popupUIParent` is a full-screen click blocker (`PopupBlockingBackground`), not the panel; the panel is `Popup/bkg` (420x320 woodpanel). Style/measure AFTER `UnifiedPopup.Push(...)`; `IsAvailable()` is false while the menu builds (pushes are dropped), so wait for it in `Update`.
9. **Joining a server from code.** `FejdStartup.SetServerToJoin()` is the wrong field (overwritten by `OnCharacterStart`). Call the private `FejdStartup.ProceedJoinRequest(ServerJoinData)` via reflection: it runs the privilege check, queues the join, and shows character selection. `-joincode` on the command line joins as the dev profile "Odev".
10. **Don't blame the game update first.** When a mod "breaks on a new version", decompile both assemblies (`game_source` after re-harvest) and diff: Valheim 1.0.7 left the equipment-modifier pipeline byte-identical to 0.221.12; the mod that died had a latent defect.
11. **BepInEx/config is wiped on every PhValheim world update.** Never store data there (see `phvalheim-worlds`).
12. **Null singletons in `Awake`.** `ZNet.instance`, `ObjectDB.instance`, `Player.m_localPlayer` are null when your plugin loads; hook game events with patches.
